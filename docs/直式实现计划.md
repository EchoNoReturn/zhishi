# 直式（ZhiShi）实现计划 v0.1 · Rust 版

对应规范：《直式语言规范草案》。目标：把直式源码编译为数学图片（SVG/PNG），并提供只做语法检查的模式。

---

## 0. 总体策略

**自己写语言层，复用渲染层。**

| 层 | 谁来做 | 说明 |
|---|---|---|
| 词法/语法分析 → AST | 我们（Rust） | 新语言的核心资产 |
| 语法检查（checker） | 我们 | 规范 §8.2 |
| AST → LaTeX 串 | 我们 | 黄金测试锁定 §6 的 20 例 |
| 排版 + 出图 | 现成引擎 | tectonic / KaTeX / MathJax（经渲染 trait 接入） |

AST 是稳定中间表示；渲染后端可替换，不动语法。

| 项 | 选择 | 理由 / 替换点 |
|---|---|---|
| 实现语言 | **Rust**（rustc 1.95+） | 性能、错误处理、CLI 分发（单二进制） |

| TeX 渲染 | **渲染 trait** + 首选后端：`tectonic`（纯 Rust TeX→PDF）或 `katex` crate / 外部 KaTeX CLI | 出图：PDF→SVG/PNG（`resvg`/`usvg` 路径或外部 `dvisvgm`/`mutool`）；替换点：MathJax（Node）覆盖最全 |

## 2. 里程碑

### M0 · 脚手架与测试地基（0.5–1 天）

- Cargo workspace、三个 crate、lint（`cargo fmt`/`clippy`）/ test 一条命令。
- `examples/`：20 个试金石 `.zsh` + 期望 `.tex`（从规范 §6 落盘）。
- 黄金 harness：`cargo test -p zhishi-tex` 遍历 examples 比对；**先让测试红着**。

**验收**：`cargo test` 可运行并报告 20 个待通过样例。

### M1 · 词法 + 语法分析器（2–4 天）

- Lexer：数字、标识符、保留字（希腊/函数/常量）、`'i`、素记号 `'`、运算符、字符串、Unicode 别名归一。
- Parser：递归下降，覆盖规范 §3 EBNF 与 §5 优先级表。
- AST 与规范构造一一对应（`/`→分数、`sup`/`sub`、`call`、`matrix`、`cases`、`align`、`set`、`prime`、`imag-unit`…）。
- 诊断：行列号 + 原文片段 + 期望记号；`x / y z` 类歧义先只报 warning。

**验收**：20 例全部 parse 成 AST 且无 error；解析错误单测 ≥ 15 条。

### M2 · 语法检查 checker（1–2 天）

- 歧义警告：链式除、`a(b)` 默认乘法但形似函数、缺括号的 `/` 分母乘积；
- 名字检查：保留字误用、未知函数、`fn` 未声明的调用形态、`fn` 重复声明；
- 结构检查：`cases` 缺 `otherwise`（warning）、`align` 的 `&=` 数量、矩阵行宽不一致。

**验收**：每类问题正/反样例；`zsc check` 输出人类可读诊断（含 `--json`）。

### M3 · TeX 后端（2–3 天）

- AST → LaTeX；`'i` → `i`、素记号 `f'(x)`、`mid` → `\mid`、`dx` 细空格、函数名直立体。
- **黄金测试**：20 例 → 期望 TeX 严格相等（空白/`{}` 归一化后）。

**验收**：20/20 通过；再手工抽 10 个随机公式目检。

### M4 · 渲染与 CLI 出图（1–2 天）

```
zsc render foo.zsh -o foo.png
zsc render foo.zsh -o foo.svg
zsc check foo.zsh
zsc ast foo.zsh
zsc tex foo.zsh
```

- 渲染 trait `Renderer { fn render(&self, tex: &str, opts: &RenderOpts) -> Result<Vec<u8>> }`。
- 首选后端按可用性探测：tectonic → 外部 `katex`/`node` → 明确报错提示安装。
- PNG 透明底、`--fontsize`、`--margin` 参数。

**验收**：20 例全部出图成功；目检 3–5 张与规范一致。

### M5 · 打磨与文档（1–2 天）

- README：安装、三个典型命令、语言速查表。
- 错误信息文案打磨（`sum_(i=1^n`、`cases{` 未闭合、`alpha` 作变量名）。
- （可选）playground：`wasm` 绑 core 做网页编辑器——Rust 侧用 `wasm-bindgen` 复用解析器。

**总量预估**：约 8–14 人天到可用的 v0.1。

## 3. 测试策略

| 层 | 方法 |
|---|---|
| lexer/parser | 单测（token 流、AST 形状）+ 解析错误诊断 |
| checker | 每条规则正/反样例 |
| tex-backend | **黄金 20 例**（文本比对）为主 |
| 渲染 | 不做像素回归；出图不失败 + 人工目检 |
| 属性测试（可选） | `proptest`：随机 AST → TeX 不抛错 |

---

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| Rust 侧渲染依赖复杂（tectonic 体积大 / 需外部 node） | 渲染与语言层严格分离；`zsc tex`/`check` 零渲染依赖可用 |
| `/` 左结合与读者直觉冲突 | checker 持续 warning；文档显著位置写明 §5.2 |
| `'i` / 素记号 `'` 词法边角 | M1 写死单测（`x'`、`'i`、`x' * 'i`、`f'(x)`） |
| TeX 黄金测试过脆 | 比对前空白/`{}` 归一化 |
| 范围蔓延 | v0.1 规范外一律拒绝进 AST，记入 v0.2 愿望单 |

---

## 5. v0.1 完成定义（DoD）

1. 20 个试金石：parse → check → tex 全绿，并能 `zsc render` 出 PNG/SVG。
2. 语法错误都有行列号与可读提示；`zsc check` 可单独使用。
3. README + 语言速查表；`examples/` 自解释。
4. `cargo fmt --check && cargo clippy && cargo test` 全绿。
5. 不做：宏系统、样式主题、交互式编辑、原生排版后端。
